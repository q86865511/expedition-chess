## 12. 風險與緩解

| ID | 風險 | 關聯需求 | 機率 | 影響 | 緩解 | 觸發條件／處置 |
|---|---|---|---|---|---|---|
| **[RSK-001]** | 32 隻完整角色加營地使切片失控 | REQ-SCOPE-002、REQ-CONTENT-001 | 高 | 高 | G0／G1／G2 三道門檻；先驗證規則再量產美術 | 任一門檻延遲超過估期 25%：停止新增內容，先完成缺失驗收 |
| **[RSK-002]** | 遠征 HP 加連敗收入鼓勵故意輸 | REQ-ECON-002、REQ-COMBAT-006、REQ-REWARD-001 | 中 | 高 | 每幕只在首次 2 連敗補助一次；依 AC-019 戰敗無戰利品 | 測試中故意輸成為最佳經濟線：降低或改為非金幣救濟 |
| **[RSK-003]** | 羈絆、裝備、遺物與技能組合爆炸 | REQ-DATA-001、REQ-COMBAT-003、REQ-EFFECT-001、REQ-EFFECT-002 | 高 | 高 | 有限 Effect 詞彙、固定順序、AC-067 型別驗證、批次模擬 | 新效果需任意腳本或產生順序歧義：拒絕內容，先擴充 typed operation |
| **[RSK-004]** | 引擎或程式變更造成決定性漂移 | REQ-COMBAT-002、REQ-RNG-001、REQ-RNG-002、REQ-DATA-005 | 中 | 高 | 整數模擬、PCG32、固定排序、canonical hashes | 任一 fixture hash 非預期變更：阻擋合併並審查規則版本 |
| **[RSK-005]** | 存檔 schema／內容 ID 更新導致壞檔 | REQ-DATA-003、REQ-DATA-006、REQ-SAVE-001、REQ-SAVE-003、REQ-SAVE-006 | 中 | 高 | Stable ID、逐版 migration、tmp、backup、fixture | migration 失敗：保留檔案、禁止覆寫、提供診斷訊息 |
| **[RSK-006]** | 無固定人口硬上限導致效能或棋盤失效 | REQ-BOARD-003、REQ-BOARD-004、REQ-UX-004 | 中 | 高 | 每版計算最大合法人口；壓測高於該值；非法格阻止開戰 | 新內容使最大值高於既有測試：同步提高測試與 UI 容量後才能發布 |
| **[RSK-007]** | 像素世界與繁中高資訊 UI 難以同時可讀 | REQ-UX-001、REQ-UX-003 | 中 | 中 | 世界／UI 分離解析度、UI 縮放、CJK 字型、可讀性測試 | 720p 出現截斷或 150% 無法操作：視為 release blocker |
| **[RSK-008]** | 與聯盟戰棋過度相似造成辨識或法律風險 | REQ-PROD-001 | 中 | 高 | 原創世界、角色、UI、命名與系統呈現；里程碑審查 | 任何素材需以 Riot 內容作直接對照才能辨識：退回重設計 |
| **[RSK-009]** | 水平解鎖稀釋商店與羈絆可達性 | REQ-META-002、REQ-META-003、REQ-CONTENT-001 | 中 | 中 | content_snapshot、解鎖池驗證、每個 profile 狀態跑模擬 | 任一解鎖組合使羈絆門檻不可達：阻止該內容組合 |
| **[RSK-010]** | VFX／BattleEvent 洪水使 presentation 落後 | REQ-COMBAT-002、REQ-UX-004 | 中 | 中 | 規則／視覺事件分級、視覺合併、物件池、64 實體壓測 | 事件佇列持續增長或 FPS 低於基線：合併純視覺事件，不丟規則事件 |
| **[RSK-011]** | 32 棋子仍形成單一最優構築 | REQ-PROD-004、REQ-QA-002 | 高 | 高 | 三種構築驗收、10,000-seed 統計、商店與羈絆熱度追蹤 | 任一構築通關率或選取率長期高出次名 20 個百分點：進行平衡迭代 |
| **[RSK-012]** | Godot 共享 Resource 被 consumer 修改而規則 hash 未更新 | REQ-DATA-001、REQ-DATA-008 | 中 | 高 | BOOT 編譯 value snapshot、deep-copy view、mutation test | UI mutation 改變 domain 值或 active digest：阻擋 build，禁止暴露原始 Resource |

## 13. 決策與假設

### 13.1 已鎖定決策

| ID | 決策 | 理由 |
|---|---|---|
| **[DEC-001]** | PC 優先、單人離線、買斷制 | 聚焦策略 UI 與本地可恢復遠征，避免後端範圍 |
| **[DEC-002]** | 戰鬥完全自動、完整敵情預覽 | 將玩家技巧集中在戰前推理與構築 |
| **[DEC-003]** | 三幕、每幕七個實際節點 | 支撐 45–60 分鐘成形曲線並維持重開成本 |
| **[DEC-004]** | 8×8 方格、常規人口 9、額外人口可疊 | 保留前後排與高人口夢幻構築 |
| **[DEC-005]** | 完整商店經濟＋玩家專屬有限池 | 保留自走棋經營深度；避免敵軍隱性消耗 |
| **[DEC-006]** | 每幕一次 2 連敗補助 | 提供翻盤但避免反覆故意戰敗農金 |
| **[DEC-007]** | 32 玩家棋子與 6＋6 雙軸羈絆 | 支撐五階商店與至少三種構築 |
| **[DEC-008]** | 6 零件／21 成裝、裝備綁定、五遺物 | 同時保留配方深度、承諾成本與可控觸發量 |
| **[DEC-009]** | 可移動營地＋水平解鎖 | 提供局外成長感，不用永久 stats 取代策略 |
| **[DEC-010]** | Godot 4.7 stable＋型別化 GDScript | 適合 2D 像素內容與小團隊資料迭代 |
| **[DEC-011]** | 純 domain 固定 tick 模擬 | 支援測試、重現、倍速與畫面分離 |
| **[DEC-012]** | PCG32 命名 stream＋版本化 JSON | 防止隨機污染、save-scum 漂移與版本壞檔 |
| **[DEC-013]** | 原創奇幻冒險 IP | 建立自身辨識度並降低侵權風險 |

### 13.2 規劃假設

| ID | 假設 | 驗證方式 | 若不成立 |
|---|---|---|---|
| **[ASM-001]** | 開發以個人＋AI 協作為主 | G0 實際工時與內容速度 | 保留規則範圍，增加人力或延後 G2 日期 |
| **[ASM-002]** | 核心客群為中度策略玩家 | G0／G1 新手測試、理解率 | 調整教學與資訊層次，不先刪核心深度 |
| **[ASM-003]** | 參考最低 PC 足以代表首發受眾 | Steam 硬體調查與實機測試 | 更新最低規格及效能 AC |
| **[ASM-004]** | 30 名熟悉規則測試者足以判斷初步時長與構築 | G2 playtest 信賴區間 | 擴大樣本，不提前宣稱平衡完成 |
| **[ASM-005]** | 文件中的 TUNE 初值可支持第一輪玩法測試 | G0 批次與人工測試 | 只調資料值；若需改語意則新增 DEC 與版本 |
| **[ASM-006]** | 首發繁中、英文預留即可滿足垂直切片 | 發行與市場規劃 | 增加翻譯內容，不改 localization 架構 |
